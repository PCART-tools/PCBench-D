The purpose of RQ2.1 is to obtain the trend patterns of API similarity/ranking across versions for the two final migration scenarios: `fix_D` and `fix_R`. The intermediate processing scripts may temporarily handle `fix_D_t`, but this scenario is not included in the final experimental results.

The ranking files and analysis scripts use the implementation identifiers `mapBased`, `tokenBased`, and `treeBased`, which correspond to the paper's **graph-based**, **token-based**, and **tree-based** algorithms, respectively; the identifiers are kept unchanged because they are part of the generated JSON keys and filenames.

## 1. Input Data

### Similarity-ranking output

The similarity-ranking output generated by `measure_similarity` is organized as follows:

```text
<root>/
└── <libname>/
    └── <fqn_D>-<fqn_R>/
        └── result/
            ├── fix_D/<query>-<candidate>/
            │   ├── mapBased.json
            │   ├── tokenBased.json
            │   └── treeBased.json
            ├── fix_D_t/<query>-<candidate>/...
            └── fix_R/<query>-<candidate>/...
```

These JSON files contain the similarity-ranking information for the replacement API, including fields such as `api_name`, `score`, and `rank`. `data2excel.py` extracts the relevant ranking information from these files and writes it into an Excel workbook for subsequent trend analysis.

### Excel input

The Excel workbook provides the API identity and version information used to locate and organize the ranking results. Each worksheet represents one library, and the worksheet name is the library name. The relevant input columns are:

```text
Column 1:  D_FQN                 Deprecated API fully qualified name
Column 2:  R_FQN                 Replacement API fully qualified name
Column 9:  bef_n_versions        Comma-separated versions before the transition
Column 10: transition_versions   Comma-separated transition versions
Column 11: aft_n_versions        Comma-separated versions after the transition
```

During intermediate processing, columns 12–14 contain the ranking JSON for `fix_D`, `fix_D_t`, and `fix_R`.

## 2. Workflow

The three scripts provide the following functions:

- `data2excel.py`: extracts similarity-ranking information from the `measure_similarity` output and records it in Excel;
- `get_rank.py`: normalizes the ranking sequences and prepares the data for trend analysis;
- `mk_analyze.py`: calculates the Mann-Kendall trend metrics for the selected API granularity.

After the intermediate processing, the final experimental data are organized according to the paper's experimental design:

1. The `fix_D_t` experiment is removed because of overlap with the other migration scenarios;
2. Experiment sequences with fewer than 10 valid versions are removed;
3. The remaining data are reorganized for presentation, producing the final output format.

## 3. Final Output Structure

The final output under `output/` contains the two retained migration scenarios:

```text
output/
├── fix_D.xlsx
└── fix_R.xlsx
```

Each workbook contains one `summary` worksheet and six data worksheets, one for each API granularity (`class` / `function` / `method`) in each transition category (`transition` / `no-transition`, i.e., the source-definition transition period present vs. absent in the paper). The current data-sheet headers are:

- `fix_D.xlsx`:
  ```text
  library | D_FQN | R_FQN | D_type | Va-1 | Vd | Vr | fix_D experimental sequence | Algorithms used | Trend_fix_D
  ```
- `fix_R.xlsx`:
  ```text
  library | D_FQN | R_FQN | D_type | Va-1 | Vd | Vr | fix_R experimental sequence | Algorithms used | Trend_fix_R
  ```

In these headers, `Va-1` is the final pre-announcement release, `Vd` the source-definition removal version, and `Vr` the original-invocation failure version (the paper's D-1, S, and F).

The experiment-result column contains the organized version-pair similarity/ranking JSON, the algorithm column records the algorithms retained for the case, and the `Trend_*` column contains the final trend-analysis result. The `summary` worksheet records the number of retained rows for each source worksheet.

The detailed descriptions of the three scripts follow.

# data2excel.py

This script is the **first step** in the RQ2.1 pipeline (trend analysis of similarity across API versions): it reads the similarity-ranking results generated by `compute_similarity.py`, compresses the target API's score / rank for each version pair into JSON strings, and writes them to columns 12–14 of the Excel file.

---

## 1. Overview

1. Reads `fqn_D` / `fqn_R` from columns 1/2, and the three version lists `bef` / `transition` / `aft` from columns 9/10/11;
2. Builds three types of version pairs (`fix_D` / `fix_D_t` / `fix_R`);
3. Reads the three algorithm JSON files under `root/<libname>/<fqn_D>-<fqn_R>/result/<fix_type>/<version_pair>/`, matches the entry where `api_name == fqn_R`, and extracts its `score` (stored as `value`), `rank`, and list length (stored as `total`);
4. Serializes the results as JSON strings, writes them to columns 12/13/14, and saves a new file as `raw_data/<excel-name>_addinfo.xlsx`.

---

## 2. Usage

```bash
python data2excel.py <input-excel-path> <result-data-root>
```

```bash
# Example: use input/class_transition.xlsx as the template
# and read ranking results from a local source-data directory
python data2excel.py input/class_transition.xlsx /path/to/output/class
```

---

## 3. Input Parameters

| Argument | Required | Description |
|---|---|---|
| `excel` (positional) | **Required** | Input Excel file; each worksheet name = library name (`libname`) |
| `root` (positional) | **Required** | Result-data root directory generated by `compute_similarity.py` |

### Required external resources

- **Input Excel file** (required): column 1 `fqn_D`, column 2 `fqn_R`, column 9 `bef`, column 10 `transition`, and column 11 `aft` (comma-separated version lists);
- **Result-data root directory `root`** (required):
  ```
  root/<libname>/<fqn_D>-<fqn_R>/result/<fix_type>/<version_pair>/
      ├── mapBased.json
      ├── tokenBased.json
      └── treeBased.json
  ```

### Version-pair construction rules

| Fix type | Source | Targets |
|---|---|---|
| `fix_D` | Last version in `bef` | `transition + aft` |
| `fix_D_t` | Last version in `transition` | `aft` |
| `fix_R` | All versions in `bef + transition` | First version in `aft` |

---

## 4. Output Structure

- Output file: `<script-directory>/raw_data/<excel-name>_addinfo.xlsx` (the original Excel file is not modified; all other columns are preserved);
- The headers in columns 12/13/14 are set to `fix_D` / `fix_D_t` / `fix_R`;
- Each row in columns 12/13/14 contains a JSON string:

```json
{"order":["1.26.5-2.0.0", ...],
 "1.26.5-2.0.0":{
   "exists":true,
   "algorithms":{
     "mapBased":   {"value":0.85,"rank":-13,"total":38},
     "tokenBased": {"value":0.62,"rank":-7,"total":38},
     "treeBased":  {"value":0.71,"rank":-2,"total":38}
   }
 }}
```

- When directories/files do not exist or the format is invalid, the script follows a best-effort strategy and returns an empty structure (`exists:false` or `null` for the corresponding algorithm).

# get_rank.py

This script is the **second step** in the RQ2.1 pipeline: it processes the version-pair ranking JSON in columns 12–14, extracts each algorithm's raw `rank`, negates it, and writes the normalized result back to the cells.

---

## 1. Overview

1. Reads the JSON in columns 12–14 (the top-level `order` field is required);
2. For each algorithm (`mapBased` / `tokenBased` / `treeBased`), extracts the `rank` sequence according to `order` and computes `rank * -1`;
3. Missing-data handling: when the result directory for a version pair does not exist (`exists=false`), the position is first recorded as `None`. A `None` at either end of the sequence is converted to a `0.0` placeholder so that it can be directly removed during subsequent processing.

> **Note on interpolation.** The script additionally performs linear interpolation on *intermediate* `None` values (a `None` with non-`None` values on both sides) and records each in `analyzed_interpolate.log`. This is **not** part of missing-data handling, and the current data contains no intermediate interpolated values: the interpolation and its log serve only as a temporary diagnostic mechanism for locating potential version/data errors — the interpolated positions found during the experiments were all data-processing errors, corrected through manual confirmation.

4. In the subsequent trend analysis in `mk_analyze.py`, consecutive `0.0` placeholders at the sequence edges are removed before the Mann-Kendall test; therefore, these boundary versions do not affect the trend result;
5. Writes the compact `{version_pair: {alg: score}}` JSON back to the cells and saves a new file.

---

## 2. Usage

```bash
python get_rank.py <input-excel-path>
```

```bash
# Example: process the output of data2excel.py
python get_rank.py raw_data/class_transition_addinfo.xlsx
```

---

## 3. Input Parameters

| Argument | Required | Description |
|---|---|---|
| `input_excel` (positional) | **Required** | Input Excel file (the output of `data2excel.py`) |

### Required external resources

- **Input Excel file** (required): cells in columns 12/13/14 contain version-pair ranking JSON with an `order` field;
- Dependency: `openpyxl`.

---

## 4. Output Structure

- Output file: `/media/he/Rbench/similarity/data_analyze/normalization/<excel-name>_rank_info.xlsx` (the filename changes from `addinfo` to `rank_info`; the input file is not modified). This is a hard-coded output directory in the script; replace it with the designated output path before running in another environment;
- Cells in columns 12–14 are replaced with compact JSON:
  ```json
  {"order":["1.26.5-2.0.0", ...], "1.26.5-2.0.0":{"mapBased":13.0,"tokenBased":7.0,"treeBased":2.0}}
  ```
- Log: `analyzed_interpolate.log` in the same directory. This is a temporary diagnostic log that records each interpolated version pair and algorithm, used to locate potential version/data errors; the current data contains no intermediate interpolated values (the interpolated versions were data-processing errors, corrected by manual confirmation).

# mk_analyze.py

This script is the **third step** in the RQ2.1 pipeline: it performs a **Mann-Kendall trend test** on the transformed replacement-rank sequences in columns 12–14 to determine whether the replacement's ranking shows a directional trend as versions evolve. The results are written to columns 15–17 as the final trend results.

---

## 1. Overview

1. Reads the b1-format similarity JSON in columns 12–14;
2. Extracts each algorithm's `rank` sequence according to `data["order"]`;
3. First removes consecutive data points at both edges of each algorithm's sequence that satisfy either of the following conditions: `rank=0.0` or `value=0.0`;
4. Computes Mann-Kendall metrics (`S` / `Z` / `p` / `sen_slope` / `trend`) on the sequence after edge-zero removal;
5. Determines which algorithms to analyze according to `--granularity` and writes the trend results to the Excel file.

---

## 2. Usage

```bash
# Function/method granularity: mapBased + tokenBased + treeBased
python mk_analyze.py normalization/xxx_rank_info.xlsx --granularity method
```

```bash
# Class granularity: mapBased + tokenBased (no treeBased)
python mk_analyze.py normalization/xxx_rank_info.xlsx --granularity class
```

---

## 3. Input Parameters

| Argument | Required | Description |
|---|---|---|
| `input_excel` (positional) | **Required** | Input Excel file (the output of `get_rank.py`) |
| `--granularity` | **Required** | API granularity: `function` / `method` / `class`, which determines the algorithm set to analyze |

### Granularity-to-algorithm mapping

| Granularity | Algorithms analyzed |
|---|---|
| `function` / `method` | `mapBased` + `tokenBased` + `treeBased` |
| `class` | `mapBased` + `tokenBased` (no `treeBased`) |

### Required external resources

- **Input Excel file** (required): columns 12/13/14 contain b1-format similarity JSON (`{"value","rank","total"}`);
- Dependency: `openpyxl`.

### MK metric definitions

The Mann-Kendall test produces several core quantities:

- `S`: Mann-Kendall statistic
- `Z`: standardized value (with tie correction)
- `p`: two-sided p-value
- `sen_slope`: Sen's slope (the median of all pairwise slopes)

The direction indicated by `S` is computed on the **negated rank** (`rank × -1`, produced by `get_rank.py`), so a better (smaller) raw rank maps to a larger value:

- `S > 0`: the negated rank rises, so the raw rank falls — the replacement's ranking **improves**;
- `S < 0`: the raw rank rises — the replacement's ranking **declines**;
- `S = 0`: no net direction.

`p` determines whether this direction reaches statistical significance, compared against the `α = 0.05` threshold passed when running the script.

Classification rules (the paper's trend categories):

| Condition | Trend label |
|---|---|
| `S > 0` and `p < α` | significant ranking improvement |
| `S > 0` and `p ≥ α` | non-significant improvement tendency |
| `S < 0` and `p < α` | significant ranking decline |
| `S < 0` and `p ≥ α` | non-significant decline tendency |
| `S = 0` | no directional trend |

The `trend` field records only the direction of `S` (`increasing` / `decreasing` / `no trend` / `insufficient data`) without distinguishing significance; `increasing` corresponds to ranking improvement and `decreasing` to ranking decline.
