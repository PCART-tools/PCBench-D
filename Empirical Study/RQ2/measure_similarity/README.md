This directory measures the similarity between deprecated APIs and replacement candidates across versions. It first constructs the version-selection plans for the experiments and then runs three similarity algorithms to rank the candidates.

The three similarity algorithms used here are named **graph-based**, **token-based**, and **tree-based** in the paper; the repository implements them as `mapBased`, `tokenBased`, and `treeBased`, and keeps this identifier spelling in code, JSON keys, and output filenames so that the documented paths match the generated artifacts.

## 1. Input Data Format

The pipeline requires the following inputs.

### Excel input

The Excel workbook used by `construct_compares.py` contains one worksheet per library. The worksheet name is the library name (`libname`), and the first row is the header. The relevant columns are:

```text
A=D_FQN  B=R_FQN  C=D_type  D=Va-1  E=Vd  F=Vr  G=D_url  H=R_url
I=bef_n_versions  J=transition_versions  K=aft_n_versions
```

The scripts use:

- column 1 `D_FQN`: fully qualified name of the deprecated API;
- column 2 `R_FQN`: fully qualified name of the replacement API;
- column 9 `bef_n_versions`: comma-separated versions before the transition;
- column 10 `transition_versions`: comma-separated transition versions;
- column 11 `aft_n_versions`: comma-separated versions after the transition.

### Extracted source-data root

The `root` directory must contain the source data generated by `lookup_source_def`, with the following structure:

```text
root/
├── <libname>/
│   ├── <fqn_D>-<fqn_R>/
│   │   ├── <fqn_D>/
│   │   │   └── <version>.py
│   │   └── R_candidates/
│   │       └── <version>/
│   │           └── <fully.qualified.name>.py
│   │       └── ...
│   └── ...
└── <libname2>/...
```

Each case should contain the deprecated API version files and the replacement-candidate version directories required by the Excel version lists.

## 2. Execution Workflow

Run the scripts in the following order:

1. **Construct comparison plans** with `construct_compares.py`:
   - read the Excel API and version information;
   - inspect the extracted source-data root;
   - select query and candidate versions for `fix_D`, `fix_D_t`, and `fix_R`;
   - write `compare_versions.json` into each case directory.
2. **Compute and rank similarities** with `compute_similarity.py`:
   - read each case's `compare_versions.json`;
   - skip experiments whose `enabled` value is `false`;
   - run `tokenBased`, `treeBased`, and `mapBased` for each enabled experiment;
   - rank candidates by similarity score.
3. **Use the ranking results** in the downstream RQ2.1 pipeline, where `data2excel.py` imports the results into Excel for subsequent rank normalization and trend analysis.

## 3. Final Output Structure

After both scripts have run, each case contains the comparison plan and the similarity-ranking results:

```text
root/
└── <libname>/
    └── <fqn_D>-<fqn_R>/
        ├── compare_versions.json
        ├── <fqn_D>/
        │   └── <version>.py
        ├── R_candidates/
        │   └── <version>/
        │       └── <fully.qualified.name>.py
        ├── result/
        │   ├── fix_D/
        │   │   └── <query>-<candidate>/
        │   │       ├── mapBased.json
        │   │       ├── tokenBased.json
        │   │       └── treeBased.json
        │   ├── fix_D_t/
        │   │   └── <query>-<candidate>/...
        │   └── fix_R/
        │       └── <query>-<candidate>/...
        └── run.log
```

Each algorithm JSON contains a similarity-ranked list, with fields such as `api_name`, `score`, and `rank`. Batch and error logs are also generated by `compute_similarity.py`.

The detailed descriptions of the individual scripts follow.

---

# construct_compares.py

This script is the **first step (version selection)** of the similarity-measurement pipeline: starting from a version-list Excel file, combined with the extracted source directories, it generates a `compare_versions.json` for each case, specifying which query / candidate version combinations the downstream similarity-ranking program should run.

---

## 1. Overview

The script reads an Excel workbook (each sheet corresponds to one library) and, combined with the extracted source directories under `root/libname/<fqn_D>-<fqn_R>/`, builds a `compare_versions.json` for each case, defining the query and candidate versions for **3 experiments** (`fix_D` / `fix_D_t` / `fix_R`):

| Experiment | Query side | Candidate side |
|---|---|---|
| `fix_D` | the **x-th-from-end** version in `bef_versions` whose source has actually been extracted | all versions under this case's `R_candidates` |
| `fix_D_t` | the **x-th-from-end** hit version in `transition_versions` | versions in `transition[idx:] + aft_versions` that actually exist |
| `fix_R` | all versions in `bef + transition` that actually exist | the **x-th-from-start** hit version in `aft_versions` |

Experiments that don't meet the conditions are written with `enabled=false` and a `reason` (e.g., missing directory, no version hit), and the downstream ranking script skips them accordingly.

* Note: later, due to overlapping experiment-scenario coverage, the fix_D_t migration scenario was removed.

---

## 2. Usage

```bash
# Build the version-selection files for the 3 experiments with a uniform x=1
python construct_compares.py \
    --root /path/to/output/function \
    --excel input/function_transition.xlsx \
    --x 1
```

```bash
# Use different x per experiment, and auto-create directories when casePath is missing
python construct_compares.py \
    --root /path/to/output/method \
    --excel input/method_transition.xlsx \
    --x-fix-d 2 --x-fix-d-t 1 --x-fix-r 1 \
    --create-missing-case
```

---

## 3. Input Parameters

| Argument | Required | Description |
|---|---|---|
| `--root` | **Required** | Case root directory, structure `root/<libname>/<fqn_D>-<fqn_R>/` (containing the `<fqn_D>/` and `R_candidates/` directories) |
| `--excel` | **Required** | Input Excel file; each sheet name = library name (libname) |
| `--x` | Optional | Uniform default x for all three experiments, default `1` |
| `--x-fix-d` | Optional | x for the `fix_D` experiment (count from end), falls back to `--x` |
| `--x-fix-d-t` | Optional | x for the `fix_D_t` experiment (count from end), falls back to `--x` |
| `--x-fix-r` | Optional | x for the `fix_R` experiment (count from start), falls back to `--x` |
| `--create-missing-case` | Optional | Auto-create the directory and write the JSON when casePath is missing |

### Required external resources

- **Excel file** (required): reads 5 columns — column 1 `fqn_D`, column 2 `fqn_R`, and columns 9/10/11 as comma-separated version lists `bef_versions` / `transition_versions` / `aft_versions`.
- **Case root directory `root`** (required): the output directory of `extract_and_save.py`; each case already has `<fqn_D>/<version>.py` (deprecated API source) and `R_candidates/<version>/` (replacement candidate source).

### Meaning of the x parameter

- For `fix_D` / `fix_D_t`, x is the **x-th-from-end** hit version (`pick_kth_hit_from_end`, counting backward from the end of the list);
- For `fix_R`, x is the **x-th-from-start** hit version (`pick_kth_hit_from_start`, counting forward from the start).

---

## 4. Output Structure

For each case, writes `root/<libname>/<fqn_D>-<fqn_R>/compare_versions.json`:

```json
{
  "schema_version": 2,
  "meta": {
    "lib": "<libname>",
    "case_dirname": "<fqn_D>-<fqn_R>",
    "fqn_D": "...",
    "fqn_R": "...",
    "x": { "fix_D": 1, "fix_D_t": 1, "fix_R": 1 }
  },
  "inputs": {
    "bef_versions": [...],
    "transition_versions": [...],
    "aft_versions": [...],
    "D_has_versions": [...],
    "R_has_versions": [...]
  },
  "experiments": {
    "fix_D":   { "enabled": true/false, "query": "...", "candidates": [...], "reason": "" },
    "fix_D_t": { "enabled": true/false, "query": "...", "candidates": [...], "reason": "" },
    "fix_R":   { "enabled": true/false, "queries": [...], "candidate": "...", "reason": "" }
  }
}
```

- The console finally prints `total_rows / written / skipped` statistics;
- `skipped` is the number of cases whose casePath is missing and where `--create-missing-case` was not passed.

# compute_similarity.py

This script is the **second step (computation and ranking)** of the similarity-measurement pipeline: it walks `root/<libname>/<cur>`, reads each cur's `compare_versions.json`, and for each `enabled=true` experiment runs the tokenBased / treeBased / mapBased algorithms in turn, producing ranking results sorted by descending similarity.

---

## 1. Overview

1. Walks all `libname/cur` under `root` (the cur directory name is `fqn_D-fqn_R`);
2. Reads `cur/compare_versions.json`, parses the query / candidate versions and the `enabled` flag of the 3 experiments (`fix_D` / `fix_D_t` / `fix_R`); experiments with `enabled=false` are skipped;
3. For each experiment: first **compiles the query representations** with the algorithm, then **computes similarity against each candidate concurrently** using a process pool (spawn mode, 80 workers by default);
4. Sorts results by score in descending order and assigns competition ranks: tied scores receive the same rank, with subsequent ranks skipping positions (for example, `1, 1, 3`);
5. Outputs are isolated per experiment, written to `<cur>/result/<experiment>/<query>-<candidate>/<algorithm>.json`.

---

## 2. Usage

```bash
# Run all 3 experiments for all curs under root
python compute_similarity.py /path/to/output/function
```

```bash
# Run only the fix_D and fix_R experiments, with candidate concurrency capped at 40
python compute_similarity.py /path/to/output/method \
    --only-experiments fix_D,fix_R \
    --candidates-workers 40
```

```bash
# Force re-run, overwriting the existing main log
python compute_similarity.py /path/to/output/class --overwrite
```

---

## 3. Input Parameters

| Argument | Required | Description |
|---|---|---|
| `root` (positional) | **Required** | Root directory to process, structure `root/<libname>/<cur>/` |
| `--overwrite` | Optional | Continue and overwrite the main log if it already exists (default: exit) |
| `--only-experiments` | Optional | Run only the specified experiments, comma-separated: `fix_D,fix_D_t,fix_R`; default: all |
| `--candidates-workers` | Optional | Overrides `CANDIDATES_WORKERS` (0=auto, >0=concurrency cap, default 80) |
| `--rank-worker-max-tasks` | Optional | Overrides `RANK_WORKER_MAX_TASKS` (max task reuse per candidate subprocess, default 2) |

### Required external resources

- **`root` directory** (required): the output directory of `construct_compares.py`; each cur must already have `compare_versions.json`, `<fqn_D>/<version>.py`, and `R_candidates/<version>/`.
- **Similarity algorithm modules**: `tokenBased.py`, `treeBased.py`, `mapBased.py` in the sibling `similarity/` directory (`treeBased` depends on the `zss` library).

### Meaning of the 3 experiments

- `fix_D`: fixes a single query on the deprecated side and ranks all candidate versions;
- `fix_D_t`: the query is a transition version, and the candidates are the versions after transition plus the after versions;
- `fix_R`: fixes a single candidate on the replacement side and ranks with the multiple queries from bef+transition.

---

## 4. Output Structure

```
<cur>/result/<experiment>/<query>-<candidate>/<algorithm>.json
# e.g.: jax/result/fix_D/1.26.5-2.0.0/tokenBased.json
```

Each JSON is a ranked list:

```json
[
  { "api_name": "jax._src.random.normal", "score": 0.87, "rank": 1 },
  { "api_name": "jax._src.random.other",   "score": 0.63, "rank": 2 }
]
```

Log artifacts:

- `cur/run.log`: per-case processing log;
- `rank_three_routes_main_<root>.log`: batch main log (success/failed cur counts, number of result files, etc.);
- `run_error/error_candidates_three_routes_<root>.log`: 5-field error details (`cur | api | algorithm | stage | reason`).
